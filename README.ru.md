# sessync

[![tests](https://github.com/latark/sessync/actions/workflows/test.yml/badge.svg)](https://github.com/latark/sessync/actions/workflows/test.yml)
[![license: MIT](https://img.shields.io/badge/license-MIT-blue.svg)](LICENSE)
![macOS](https://img.shields.io/badge/platform-macOS-lightgrey.svg)

**Сессии Claude Code на всех ваших Mac.** Продолжить разговор, начатый на другом компьютере
(`claude -r`), и искать по всей истории (`sessync find`). Сессии лежат в хранилище, которое вы
выбираете сами, — Cloudflare R2, Backblaze B2, Amazon S3, любое S3-совместимое хранилище или всё, что
умеет [rclone](https://rclone.org), — и шифруются на Mac до отправки.

[English](README.md)

![sessync: сессия с MacBook Air найдена и продолжена на Mac mini](docs/demo.gif)

Claude Code хранит каждую сессию в `~/.claude/projects/<папка-проекта>/<id>.jsonl` только на том
компьютере, где она шла, и по умолчанию удаляет их через 30 дней. Встроенной синхронизации нет.

## Что получится

- **Само.** sessync синхронизирует при старте и завершении каждой сессии `claude` и раз в 10 минут,
  пока открыт хоть один `claude`. Когда закрыта последняя сессия, в фоне ничего не работает: ни
  launchd, ни «Объектов входа».
- **Продолжить где угодно.** На другом Mac работают `claude -r <id>` и `/resume` для сессий с этого —
  и наоборот.
- **Уходят только новые строки.** Сессия — журнал, который только растёт, поэтому sessync пересылает
  его как журнал базы данных (как [Litestream](https://litestream.io/how-it-works/)): сессия на сотни
  мегабайт, в которой вы сейчас работаете, при синхронизации отправляет килобайты, а не себя целиком.
- **Ничего не теряется.** Если сессию дописывали на двух Mac между синхронизациями, под основным
  именем остаётся более длинная версия, а другая — копией рядом. Обрезанный или испорченный
  транскрипт никогда не затирает полный. Удалённые сессии 30 дней лежат в корзине. Если за раз
  удаляется больше половины файлов, синхронизация останавливается и спрашивает вас.
- **Поиск.** `sessync find слова` находит сессии, где это обсуждалось, и показывает команду, которой
  продолжить каждую.
- **Срок хранения.** sessync поднимает `cleanupPeriodDays` в Claude Code до 100 лет и возвращает из
  хранилища то, что Claude Code уже успел удалить.
- **Общая история промптов** (стрелка ↑) на всех Mac.
- **Разные имена пользователя** на разных Mac — не помеха: папки проектов пересчитываются между
  домашними папками.

## Сравнение

| | sessync | [claude-sync](https://github.com/tawanorg/claude-sync) | [claude-code-sync](https://github.com/perfectra1n/claude-code-sync) | Syncthing / Dropbox |
|---|---|---|---|---|
| Что отправляется | только дописанные строки | файлы целиком, сжатые | файлы целиком, в git | файлы целиком |
| Сессии больше 100 МБ | да | не скачиваются обратно | через Git LFS | да |
| Обрезанная копия затирает полную | нет, это конфликт | может | — | может |
| Сессию меняли на двух Mac | длинная остаётся, другая — копией | копия `.conflict` | умное слияние | копии конфликтов |
| История промптов | объединяется построчно | побеждает последняя запись | по желанию | копии конфликтов |
| Удаление | корзина 30 дней, стоп при массовом удалении, открытые сессии не трогает | сразу | зеркалирует с проверками | сразу |
| Шифрование | содержимое и имена файлов | содержимое | нет (шифруйте репозиторий сами) | у провайдера |
| Запуск | сам (hook'и Claude Code) | `push` / `pull` вручную | вручную или cron | сам |
| Поиск | `sessync find` | — | — | — |
| Платформы | macOS (Linux — следующим) | macOS, Linux, Windows | macOS, Linux, Windows | все |

## Что нужно

- macOS, [Homebrew](https://brew.sh), Claude Code в терминале.
- Хранилище: приватный бакет (бесплатного уровня Cloudflare R2 — 10 ГБ и бесплатное скачивание —
  хватит на годы сессий) или любое хранилище rclone. Подойдут и российские провайдеры S3: Timeweb
  Cloud, Selectel, Yandex Object Storage, VK Cloud — пункт «другое S3-совместимое» в `sessync setup`.

## Установка

```bash
brew install latark/tap/sessync
```

Или из git (обновления — `git pull`):

```bash
git clone https://github.com/latark/sessync.git ~/projects/sessync
~/projects/sessync/install.sh
```

`install.sh` ставит rclone, ripgrep и jq, кладёт команду `sessync` в `~/.local/bin`, добавляет два
hook'а в `~/.claude/settings.json` и поднимает срок хранения сессий (`cleanupPeriodDays`). Прежний
`settings.json` сохраняется рядом как `settings.json.bak-sessync-…`. Папку после установки не
перемещайте: команда — ссылка на неё.

Дальше в **обычном Терминале** (не через `!` внутри Claude — ввод не должен попасть в переписку):

```bash
sessync setup     # хранилище, ключи, пароль шифрования, hook'и Claude Code
sessync           # первая синхронизация
sessync export    # по шагам сохранить ключи и пароль в «Пароли»
```

**Хранилище.** `sessync setup` предлагает Cloudflare R2, Backblaze B2, Amazon S3, любое
S3-совместимое хранилище (по адресу endpoint) или любое хранилище rclone — Google Drive, Dropbox,
OneDrive, SFTP, WebDAV/Nextcloud, NAS, — заранее настроенное в `rclone config`. Для бакета создайте
**приватный**, только для сессий, и ключ с доступом только к нему: основной ключ аккаунта открывает
все ваши бакеты.

**Пароль шифрования — единственный способ прочитать данные.** Потеряете его — хранилище останется
нечитаемым навсегда. На первом Mac на вопрос о пароле нажмите Enter — будет создан случайный, затем
выполните `sessync export`. Он открывает «Пароли» и ведёт по шагам: по одному кладёт ключи и пароль
в буфер обмена только этого Mac (без «Универсального буфера», с пометкой «скрытое», поэтому менеджеры
истории буфера — Raycast, Alfred, Maccy, Paste — их не запоминают) и в конце очищает буфер. Запись
сама появится на других ваших устройствах через iCloud.

### Остальные Mac

1. Установить так же.
2. `sessync setup` — то же хранилище, те же ключи и **тот же пароль** (из записи в «Паролях»).
   С другим паролем sessync откажется работать и ничего не запишет.
3. `sessync` — скачает всё.

## Как пользоваться

Обычно — никак: всё происходит само. Чтобы пересесть за другой Mac, выполните на первом `sessync`
(или просто закройте `claude`), запустите `claude` на втором — сессии с первого появятся в `/resume`.
Или найдите нужную:

```bash
sessync find договор аренды     # сессии, где в переписке есть все эти слова
sessync find "точная фраза"
sessync find -p my-site деплой   # только в проектах, где в пути есть my-site
sessync find                     # последние сессии во всех проектах
```

Для каждой сессии — когда была, в какой папке, заголовок, фрагмент с совпадением и готовая команда
вроде `cd ~/projects/my-site && claude -r 3bb6f76a-…`. Поиск идёт по самой переписке — ваши сообщения
и ответы Claude, без служебных вставок и вывода команд (их ищет `--raw`).

| Команда | Что делает |
|---|---|
| `sessync` | синхронизировать сейчас |
| `sessync status` | когда и что синхронизировано, ошибки, конфликты; `--remote` — объём в хранилище |
| `sessync find …` | поиск по всем сессиям |
| `sessync off` / `on` | выключить / включить автоматическую синхронизацию |
| `sessync conflicts` | сессии, менявшиеся на двух Mac (`--delete` — удалить копии) |
| `sessync trash` | удалённые сессии в корзине хранилища |
| `sessync restore <id>` | вернуть сессию из корзины |
| `sessync deletes` | синхронизация остановлена из-за массового удаления: `--undo` — вернуть, `--apply` — удалить везде |
| `sessync setup` | хранилище (`--storage` — сменить), ключи, пароль |
| `sessync export` | сохранить ключи и пароль в «Пароли» |
| `sessync hooks install` / `remove` | hook'и Claude Code |
| `sessync log` | последние строки журнала |

Интерфейс по-русски, если язык системы русский, иначе по-английски (выбрать явно — `LANGUAGE=ru` или
`LANGUAGE=en` в `~/.config/sessync/config`).

## Строка статуса

Если в `settings.json` уже есть своя строка статуса (`statusLine`), добавьте в её вывод
`$(sessync statusline)`. Если нет — можно показывать только синхронизацию:

```json
"statusLine": { "type": "command", "command": "sessync statusline" }
```

`сессии ↻ 13:26` (приглушённо) — всё в порядке, время последней синхронизации, жёлтым — если её не
было больше 30 минут; `сессии: <что случилось>` (жёлтым) — ошибка; `сессии: конфликт N` (красным);
`сессии: синхр. выкл`. Об ошибке и новом конфликте ещё приходит уведомление macOS — один раз.

## Подсказка для Claude

Чтобы Claude в любом проекте знал про архив, добавьте в `~/.claude/CLAUDE.md`:

```markdown
## История сессий на всех Mac
- Сессии всех Mac синхронизирует sessync (зашифрованное хранилище). Прошлые разговоры из любого
  проекта ищи через `sessync find слово …` (`--raw` — и по выводу инструментов), продолжить
  найденную — `cd <папка> && claude -r <id>`.
- Транскрипты (`~/.claude/projects/**/*.jsonl`) и `~/.claude/history.jsonl` не клади в git и не
  публикуй: в них вся переписка, включая прочитанные файлы с ключами.
- Ключи хранилища и пароль шифрования — в Связке ключей: никогда не выводи их значения в чат и в
  логи. Ввод — только `sessync setup` в терминале пользователя.
```

## Разные имена пользователя

Claude Code называет папку проекта по полному пути (`/Users/ann/work/site` → `-Users-ann-work-site`).
Хранилище запоминает домашнюю папку первого Mac; на Mac с другой (`/Users/bob`) папки проектов внутри
неё переименовываются на входе и выходе, как и пути проектов в истории промптов. Текст переписки
остаётся байт в байт (в старых сообщениях — прежний путь, на продолжение сессии это не влияет).
Проекты вне домашней папки должны лежать по одинаковому пути на всех Mac. Очень длинные пути,
которые Claude Code сокращает хэшем, пересчитать нельзя.

## Корзина

Удалённая на любом Mac сессия сначала копируется в `trash/<дата>/` внутри того же хранилища — без
скачивания, зашифрованной, как и всё остальное, — и только потом удаляется. Через 30 дней копия
удаляется сама (`TRASH_DAYS=…` в настройках).

```bash
sessync trash               # что лежит в корзине и когда удалено
sessync restore 3bb6f76a    # вернуть сессию (id или часть пути) — с её вложениями
sessync                     # вернётся в хранилище и на другие Mac
```

Старые версии сессий не хранятся: транскрипт только дописывается, и каждая версия целиком содержит
предыдущую.

## Посмотреть и удалить сессии

- `claude --resume`: `Ctrl+A` — сессии всех проектов, пробел — просмотр, `Ctrl+R` — переименовать.
- [Agent Sessions](https://github.com/jazzyalex/agent-sessions) — приложение для macOS, чтобы читать
  старые разговоры целиком. Переписку только читает. На первом экране выключите «Enable Quota
  Meter», если лимиты не нужны (иначе приложение читает токен входа Claude Code из Связки ключей), и
  не включайте его tmux-зонд: он запускает `claude` в своей папке, и sessync разнесёт эти служебные
  сессии по всем Mac.
- Удалить проект целиком — `claude purge <папка>` (встроено в Claude Code). Удалится и на других Mac
  и 30 дней пролежит в корзине.
- Удалить одну сессию — файл `<id>.jsonl` и папку `<id>/` рядом с ним (субагенты, вложения).

## Безопасность

Коротко: содержимое и имена файлов шифруются на вашем Mac (rclone crypt); хранилище видит
зашифрованные объекты, их размеры и время. Ключи и пароль — в Связке ключей. Всё, что sessync пишет
на диск, доступно только вашему пользователю. Подробно и модель угроз — [SECURITY.md](SECURITY.md).

## Ограничения

- Пока только macOS. Следующим — Linux.
- Синхронизация не мгновенная: при старте и конце сессии и раз в 10 минут. Перед тем как пересесть —
  `sessync`.
- Не продолжайте одну и ту же сессию на двух Mac одновременно.
- Удаление на одном Mac доходит до остальных (а копия 30 дней лежит в корзине).
- Синхронизируются только сессии и история промптов. Настройки, плагины, навыки, точки отката
  `/rewind` и папки `memory/` — нет: держите их в git-репозитории своего `~/.claude`.
- sessync опирается на то, что Claude Code только дописывает транскрипты. Если это изменится,
  sessync придётся менять.

## Если что-то не так

| В строке статуса / `sessync status` | Что делать |
|---|---|
| `не настроено (sessync setup)` | выполнить `sessync setup` в Терминале |
| `нет доступа к хранилищу …` | интернет, имя бакета, ключи (`sessync setup`), баланс у провайдера |
| `пароль шифрования не тот, что на других Mac` | `sessync setup` и пароль из «Паролей» |
| `settings.json не читается` | в `~/.claude/settings.json` ошибка; `jq . ~/.claude/settings.json` покажет где |
| `не завершилась (код …)` | чаще всего сеть; повторится само, подробности — `sessync log` |
| `остановлено: слишком много удалений` | `sessync deletes` покажет, что и где; по ошибке — `--undo`, намеренно — `--apply` |
| `хранилище в формате новее этой версии` | на другом Mac более новый sessync: обновите этот |
| `сессии ↻ …` жёлтым | давно не было синхронизации: `sessync status`, возможно, нет сети |

Журнал — `~/.local/state/sessync/sync.log`.

## Удаление

```bash
./uninstall.sh            # убрать hook'и и команду; ключи, пароль и данные остаются
./uninstall.sh --purge    # ещё и ключи с паролем из Связки ключей, локальное состояние, индекс поиска
```

С Homebrew: `$(brew --prefix sessync)/libexec/uninstall.sh` (можно с `--purge`), затем
`brew uninstall sessync`.

Данные в хранилище не трогаются — удалите бакет в панели провайдера, если он больше не нужен.
`cleanupPeriodDays` остаётся прежним: верните 30, если хотите, чтобы старые сессии снова удалялись.

## Как устроено

- Всё в хранилище зашифровано `rclone crypt`: и содержимое, и имена. Синхронизирует `lib/engine.py`
  (python3 без зависимостей поверх rclone). Папки `memory/` не синхронизируются.
- **Транскрипты** (`*.jsonl`) только дописываются, поэтому пересылаются как журнал. В хранилище у
  сессии лежит **основа** (полная копия на какой-то момент) и **хвосты** — объекты с дописанными
  после неё строками. Отправляются только новые целые строки; другой Mac скачивает только новые
  хвосты и дописывает их в конец своего файла или читает нужный кусок из середины (зашифрованный
  файл можно читать с любого места).

  ```
  Mac A       session.jsonl   ████████████████████████▒▒░
  хранилище                   [ основа 9,4 МБ         ][хвост][хвост]   ← каждая синхронизация — хвост
  Mac B       session.jsonl   ████████████████████████▒   + новый хвост → те же байты
  ```
- **Сжатие** делает Mac, дописавший последним. Сессия затихла на час — её хвосты сворачиваются в
  один; 48 хвостов сворачиваются, даже если сессия идёт; хвосты по объёму догнали основу — сессия
  уходит целиком новой основой. Основа каждый раз хотя бы вдвое больше прежней, поэтому в сумме на
  сессию уходит не больше двух её размеров.
- **Вложения** (вывод команд, картинки, копии конфликтов) пишутся один раз и уходят целиком. Ссылки
  (субагенты) уходят ссылками.
- **Конфликт.** Сессию меняли на двух Mac между синхронизациями — под основным именем остаётся
  более длинная версия, другая — `<id>.jsonl.conflict1` рядом. Транскрипт, ставший короче, — тоже
  конфликт.
- **Удаление.** Удалённое здесь сначала копируется в корзину. Сессию, удалённую на другом Mac, но
  открытую здесь (реестр Claude Code `~/.claude/sessions/`), sessync удалит здесь после её закрытия.
- **История промптов.** У каждого Mac свой файл в хранилище (имя Mac + начало его аппаратного UUID),
  он только дописывается; на каждом Mac все файлы объединяются построчно, без повторов.
- **Формат** хранилища записан в контрольном файле. Более новый формат останавливает старые версии,
  а не даёт им писать по-старому.
- **Состояние этого Mac** — `~/.local/state/sessync/` (журнал, метки для строки статуса, состояние
  движка); настройки — `~/.config/sessync/config`; индекс поиска — `~/.cache/sessync/find`.
- **Проверка** — `tests/run.sh`: несколько «Mac» и локальная папка вместо хранилища; Связку ключей и
  настоящий `~/.claude` не трогает.
